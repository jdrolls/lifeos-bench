# Operational Rules

> Fictional benchmark persona.

- **TypeScript on Bun always.** Never Python unless Bruce explicitly approves it for that task.
- **Never npm/npx.** Use bun/bunx.
- **Explicit code over clever code.** A junior should read it once and be right about it.
- **Plan means stop.** "Create a plan" means present the plan and wait. No execution.
- **Build over ask for reversible actions.** Editing a file or running a test does not need
  permission. Deleting, deploying, or pushing does.
- **Verify before claiming success.** Tests, diffs, or output. "Should work" is not a result.
- **One change at a time when debugging.** Isolate, verify, proceed.
- **24h time, YYYY-MM-DD dates.** Always.
- **Deep-work block is 22:00–02:00.** Do not propose morning working sessions; mornings
  belong to the board and are not available for focused work.
- **One source of truth per thing.** Do not create a second copy of state that already exists.
